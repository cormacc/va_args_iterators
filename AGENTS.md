# AGENTS.md

Header-only C preprocessor library to count and iterate over `__VA_ARGS__`. The user documentation is `README.org`.

## Commands

Run all commands in the Nix devShell (`flake.nix`: cmake, ruby, stdenv gcc). direnv loads it through `.envrc`; otherwise prefix a command with `nix develop -c`.

```sh
# Build and run the unit tests (C++20, Catch2 v2.13.9 single header in vendor/catch)
cmake -S . -B build && cmake --build build && ./build/tests

# Regenerate pp_iter.h (default limit 63 args); extra args pass through to the generator
./regenerate                      # = ruby pp_iterators.rb "$@" > pp_iter.h
ruby pp_iterators.rb --help       # generator options (only --limit N)
ruby pp_iterators.rb --limit 127 > pp_iter.h

# Show the preprocessed test source, to debug macro expansion
./inspect_macro_expansion         # = gcc -I . -I ./vendor/catch -E test/pp_iter_test.cpp
```

`CMakeLists.txt` declares `cmake_minimum_required(VERSION 3.12...4.4)`: 3.12 is the minimum for `CXX_STANDARD 20`, and 4.4 is the newest version tested. Raise the upper bound when you test a newer CMake. The expected result is `All tests passed (71 assertions in 9 test cases)`.

To check the committed header against the generator, regenerate to `.tmp/` and diff without the `Autogenerated on` and `- Script:` lines.

## Architecture

- `pp_iterators.rb` is the source of truth. `pp_iter.h` is generated output: do not edit it by hand. Change the generator, regenerate, then commit both. The header records the generation timestamp and the `--limit` value, so a regeneration always produces a diff.
- `PPIterators` (in `pp_iterators.rb`) has one method for each macro group (`defer`, `eval`, `concat`, `logical`, `lists`, `tuples`, `narg`, `each`, `each_with_index`, `parameterised_each_with_index`, `list_each`, ...). `embed_macros` sets their order in the header; `generate_header` wraps them. `PPIterators::CFile` is the helper for include guards, indentation and `#define` lists. Other code generators (for example the fake function framework) can `require` this file and call the methods to emit a subset of the macros.
- Each group has its own include guard (`PP_EACH`, `PP_NARG`, `DEFER`, `EVAL`, ...), so the macros can be embedded in other headers without a clash.
- Iteration (`PP_EACH`, `PP_EACH_IDX`, `PP_PAR_EACH_IDX`, `PP_COMMA_EACH`) is recursive. It uses `DEFER`/`EVAL` and pattern-matching macros (`IF`, `NOT`, `PP_MATCHER`, tuple-aware `CAT`), after Saad Ahmad's blog posts. The `EVAL` depth is `ceil(log2(limit))` levels. Indices come from `PP_SEQ_N()`, so the argument limit also bounds the index range.
- The header requires `__VA_OPT__`; there are no compiler-specific code paths. `PP_NARG` is `_0 __VA_OPT__(,) __VA_ARGS__` counted against `PP_RSEQ_N()`, and `IS_EMPTY` is `NOT(PP_NARG(...))`. `narg_common` defines the probe `PP_HAS_VA_OPT` and emits `#error` when it is 0; argument counting is emitted first so that this error comes first.
- The minimum supported embedded compiler is Microchip XC-DSC v4.00 (GCC 8.3.1 based, C only). It supports `__VA_OPT__` in all C modes; strict `-std=c99`/`c11`/`c17` with `-pedantic` warns about it. The Nix devShell does not provide XC-DSC.
- `pp_enum.h` is hand-written. It builds on `pp_iter.h` and provides `TAGGED_ENUM`, `TAGGED_ENUM_TYPE`, `ENUM_DESCRIBE` and `ENUM_DESCRIBE_EXPLICIT`, which generate `<Name>_COUNT` and `<Name>_asCString`. It reads the member list from a user macro named `<Name>Tags` (`ENUM` uses `NAME##Tags`).
- Tests: `test/pp_iter_test.cpp` (`SCENARIO` blocks for each `pp_iter.h` macro, and the Catch main) and `test/pp_enum_test.cpp`. The 63-argument tests in `PP_NARG` and `PP_EACH` assume the default limit, so a header generated with a lower `--limit` does not compile against them.
- MSVC needs its conformant preprocessor (`/Zc:preprocessor`, VS 2019 16.5 or later) for `__VA_OPT__`; `CMakeLists.txt` sets it. MSVC support is optional and untested; only current versions matter. MSVC enforces the C standard minimum of 127 macro arguments; this is why the default limit is 63.

## Earlier versions

- The tag `legacy-preprocessors` (`e6a5190`) is the last version with fallbacks for preprocessors without `__VA_OPT__`, and the remote branch `non-recursive` holds a generator variant that does not use recursion. `README.org` points users to both. Do not reintroduce either on `master`. The tag also has the removed `PP_1PAR_EACH_IDX`/`PP_2PAR_EACH_IDX` wrappers and the unused `DEFER3`-`DEFER6`, `EVAL_`, `TEST_LAST` and `PAREN` macros.
