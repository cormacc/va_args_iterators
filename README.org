* Description
This repository includes the following:
- [[file:./pp_iter.h][pp_iter.h]] :: Some C macros (and an associated [[file:pp_iterators.rb][code generator]]) to count and iterate over variadic macro arguments.
- [[file:./pp_enum.h][pp_enum.h]] :: A set of macros building on those defined in pp_iter.h to facilitate auto-generation of string representations of members of an enum type.

The included =pp_iter.h= includes macros to handle up to 63 arguments. Behaviour beyond this is undefined.
The Ruby code generator script can be used to generate a header supporting larger numbers of variadic arguments if required.

The C99 and C11 standard specifies that a compiler must handle a program with a macro with 127 arguments, so behaviour beyond this limit will be undefined. In theory, this only guarantees operation of the counting macros up to about 63 arguments, at least using this implementation.

In my experience, MSVC appears to enforce the 127-argument limit, whereas gcc handled 512 without difficulties (didn't test any higher arg count).

* Compiler compatibility
=pp_iter.h= requires a preprocessor that supports =__VA_OPT__=, and stops with =#error= if it does not. =__VA_OPT__= is standard in C++20 and C23, and GCC also accepts it in older C and C++ modes. In strict modes such as =-std=c99 -pedantic=, GCC would warn about =__VA_OPT__= and about variadic macros called with no variadic arguments; both headers use =#pragma GCC system_header= to suppress these warnings, and warnings about the arguments that you pass to the macros are still reported. The oldest compiler tested is Microchip XC-DSC v4.00 (based on GCC 8.3.1). MSVC needs its conformant preprocessor (=/Zc:preprocessor=, Visual Studio 2019 16.5 or later); it is not tested.

With =__VA_OPT__=, =PP_NARG()= evaluates to 0, and the iteration macros accept an empty argument list, in every language mode.

For a preprocessor without =__VA_OPT__=, use an earlier version:
- The =legacy-preprocessors= tag is the last version without the =__VA_OPT__= requirement. It uses =__VA_OPT__= when available, else the GCC =, ##__VA_ARGS__= extension, else a standard-only fallback that cannot count zero arguments.
- The =non-recursive= branch has an older generator that can also generate =pp_iter.h= without recursion, for preprocessors such as the traditional MSVC preprocessor.

* Usage instructions

** Macros
This family of macros is intended to allow the transformation of a =__VA_ARGS__= list into a single C expression OR one C expression per argument. In the latter case, the transformation macro should include the concluding semi-colon. The two indexed macro variants use 0-based indexing.

*** PP_EACH(TF, ...)
Iterates over a set of variadic macro arguments and applies a provided transformation macro (=TF(ARG)=) to each argument =ARG=.

*** PP_EACH_IDX(TF, ...)
Iterates over a set of variadic macro arguments and applies a provided transformation macro =TF(ARG, IDX)= to each argument =ARG= and index =IDX=.

*** PP_PAR_EACH_IDX(TF, (FIXED_ARGS), ...)
Iterates over a set of variadic macro arguments and applies a provided transformation macro =TF(FIXED_ARG1, [...additional fixed args,], ARG, IDX)= to each argument =ARG= and index =IDX=.

Put the fixed arguments in parentheses, e.g. =PP_PAR_EACH_IDX(TF, (FIXED_ARG1, FIXED_ARG2), VAR_ARG_1, VAR_ARG_2)=. Two or more fixed arguments must have the parentheses. A single fixed argument can be given without them, e.g. =PP_PAR_EACH_IDX(TF, FIXED_ARG1, VAR_ARG_1, VAR_ARG_2)=.

I use it when mocking dependencies (using ceedling and fake function framework)
for shorthand verification of function calls, i.e.

#+BEGIN_SRC c
  TEST_ASSERT_CALLED_WITH(RgbPixel_render, &rendered_pixel, TEST_COLOUR, TEST_INTENSITY);
#+END_SRC

... rather than ...
#+BEGIN_SRC c
  TEST_ASSERT_EQUAL(1, RgbPixel_render_fake.call_count);
  TEST_ASSERT_EQUAL(&rendered_pixel, RgbPixel_render_fake.arg0_val);
  TEST_ASSERT_EQUAL(TEST_COLOUR, RgbPixel_render_fake.arg1_val);
  TEST_ASSERT_EQUAL(TEST_INTENSITY, RgbPixel_render_fake.arg2_val);
#+END_SRC

... which is facilitated by ....
#+BEGIN_SRC c
  #define _FFF_VERIFY_PARAMETER_(FN, VAL, IDX) TEST_ASSERT_EQUAL(VAL, FN##_fake.arg##IDX##_val);
  #define TEST_ASSERT_CALLED_WITH(FN, ...)                        \
      TEST_ASSERT_CALLED(FN);                                     \
      PP_PAR_EACH_IDX(_FFF_VERIFY_PARAMETER_, (FN), __VA_ARGS__)
#+END_SRC

*** PP_COMMA_EACH(TF, ...)
A variant of PP_EACH that comma-separates the results of transformation.
This is useful if you need to generate a list of arguments to a function.
=pp_enum.h= uses PP_EACH with a transformation macro that appends ',' to build an array initialiser. That leaves a trailing ',', which is valid in an enum definition or array initialiser, but not in a function call.

Contributed by [[https://github.com/ondrejpopp][OndrejPopp]]


*** Removed macros

The original implementation required separate parameterised macro sets to be defined for a given number of fixed arguments. Parenthesised fixed arguments made them unnecessary, and the wrapper macros have been removed. Replace them as follows:

| Removed syntax                          | Replacement                              |
|-----------------------------------------+------------------------------------------|
| PP_1PAR_EACH_IDX(TF, FARG, ...)         | PP_PAR_EACH_IDX(TF, (FARG), ...)         |
| PP_2PAR_EACH_IDX(TF, FARG1, FARG2, ...) | PP_PAR_EACH_IDX(TF, (FARG1, FARG2), ...) |

The =legacy-preprocessors= tag still has the wrapper macros and the generator method that defines them.

All macros in =pp_iter.h= start with =PP_=, so that they do not clash with macros in your code. The helper macros =IF=, =NOT=, =CAT=, =EVAL=, =DEFER=, =DEFER2=, =HEAD=, =TAIL=, =EAT=, =DEPAREN=, =OPT_DEPAREN=, =IS_EMPTY=, =NOT_EMPTY=, =IS_ENCLOSED= and =IF_ENCLOSED= are renamed with a =PP_= prefix (e.g. =PP_IF=). Macros that start with =PP_I_= are internal, and can change without notice.

** Generator
This repository includes a pre-generated header to handle up to 63 =__VA_ARGS__=. A header to handle an arbitrary number of arguments may be generated using the included generator script (written in ruby), as follows:

#+BEGIN_SRC sh
  ruby pp_iterators.rb --limit <NARGS>
#+END_SRC

By default, the script just prints the header content to the console, so you'll want to redirect to file.

e.g. for up to 127 args
#+BEGIN_SRC sh
  ruby pp_iterators.rb --limit 127 > pp_iter.h
#+END_SRC

When called without any arguments, the default value of 63 will be used.

The generator provides a set of methods which may be used in 3rd party code generators. These support generation of the macros described above, and of variants of the argument counting macros (=narg_minus(n)= defines =PP_NARG_MINUS<n>=, which counts the arguments after the first =n=). The [[https://github.com/meekrosoft/fff][fake function framework]] is an example of a generator that uses them.

The argument counting macros need the common definitions from =narg_common=:

#+BEGIN_SRC ruby
  require './pp_iterators'
  ppi = PPIterators.new(nargs_max: 127)
  puts <<~EOH
  // Define the counting macros PP_NARG and PP_NARG_MINUS2
  #{ppi.narg_common}
  #{ppi.narg}
  #{ppi.narg_minus(2)}
  EOH
#+END_SRC

The iteration macros (=each=, =each_with_index=, =parameterised_each_with_index= and =list_each=) depend on most of the other definitions. To emit them, use =embed_macros= (the header body) or =generate_header= (the complete header).

*** Embedding the macros in another generator's header
These methods are the supported Ruby API for external generators:
- =PPIterators.new(nargs_max: 63)= :: the argument limit; at least 2.
- =embed_macros(require_va_opt: true)= :: all the macros, with their =PP_*_H= include guards. With =require_va_opt: false= the text has no =__VA_OPT__= probe and no =#error=, and it does not depend on the =#if= that you put around it.
- =va_opt_probe= :: only the =__VA_OPT__= probe, which defines =PP_HAS_VA_OPT= as 1 or 0. It has its own include guard, and it does not define =PP_HAS_VA_OPT= if it is already defined, so that =-DPP_HAS_VA_OPT=0= forces the embedded macros off.
- =narg_common(require_va_opt: true)= and =narg_minus(m)= :: the common counting definitions, and =PP_NARG_MINUS<m>=.

To make =__VA_OPT__= a requirement for the embedded macros only, not for the whole host header, emit the probe and put the macros in =#if PP_HAS_VA_OPT=:

#+BEGIN_SRC ruby
  require './pp_iterators'
  ppi = PPIterators.new(nargs_max: 63)
  puts <<~EOH
  #{ppi.va_opt_probe}
  #if PP_HAS_VA_OPT
  #{ppi.embed_macros(require_va_opt: false)}
  #endif
  EOH
#+END_SRC

Because the include guards are the same, a standalone =pp_iter.h= included after the host header skips the groups that the host header defines. The standalone =pp_iter.h= always uses its own probe: it ignores a predefined =PP_HAS_VA_OPT=, and stops with =#error= if =__VA_OPT__= is missing. [[./test/embed_host.rb]] generates such a host header for the =embed_tests= and =embed_tests_no_va_opt= tests.

* Usage example :: auto-generation of string descriptors for an enum type
  The file [[file:pp_enum.h][pp_enum.h]] uses =PP_EACH= to support autogeneration of textual descriptions of enum members. This saves some repetition and eliminates the risk of forgetting to update the tag when adding/re-arranging members.

  The member list is a macro named =<Name>IDs=: it holds the identifiers of the members (C calls them enumerators). The tags are the strings that the macros make from them.

  Versions before 2026-11-18 named the list =<Name>Tags=. To upgrade, rename each =#define <Name>Tags= to =#define <Name>IDs=; nothing else refers to the list. =TAGGED_ENUM= and the other declaring macros now also declare =<Name>_fromCString=, which =ENUM_DESCRIBE= defines.

** my_tagged_enum.h

*** Untyped enum

#+BEGIN_SRC c
  #include "pp_enum.h"
  #define FavouritePiperIDs                    \
      WILLIE_CLANCY,                          \
      SEAMUS_ENNIS,                           \
      TOMMY_RECK

  TAGGED_ENUM(FavouritePiper);
#+END_SRC

 ... which expands to ...

#+BEGIN_SRC c
  enum FavouritePiper {
      WILLIE_CLANCY,
      SEAMUS_ENNIS,
      TOMMY_RECK,
      FavouritePiper_COUNT
  };

  char const * FavouritePiper_asCString(int id);
  int FavouritePiper_fromCString(char const * tag);
#+END_SRC

*** Typed enum

#+BEGIN_SRC c
  #include "pp_enum.h"
  #define FavouritePiperIDs                     \
      WILLIE_CLANCY,                           \
      SEAMUS_ENNIS,                            \
      TOMMY_RECK

  TAGGED_ENUM_TYPE(FavouritePiper);
#+END_SRC

... which expands to ...

#+BEGIN_SRC c
  typedef enum {
      WILLIE_CLANCY,
      SEAMUS_ENNIS,
      TOMMY_RECK,
      FavouritePiper_COUNT
  } FavouritePiper;

  char const * FavouritePiper_asCString(int id);
  int FavouritePiper_fromCString(char const * tag);
#+END_SRC

=ENUM(FavouritePiper)= and =ENUM_TYPE(FavouritePiper)= create the same enum without the function declarations.

** my_tagged_enum.c

*** Automatic tag generation
(This uses the =PP_EACH= macro)
Assuming =my_tagged_enum.h= contains the listing provided above for either the typed or untyped enum example...

#+BEGIN_SRC c
  #include "my_tagged_enum.h"

  ENUM_DESCRIBE(FavouritePiper);
#+END_SRC

... which expands to ...

#+BEGIN_SRC c
  static char const * FavouritePiper_TAGS[] = {
      "WILLIE_CLANCY",
      "SEAMUS_ENNIS",
      "TOMMY_RECK",
  };

  char const * FavouritePiper_asCString(int id) { return (unsigned)id < (unsigned)FavouritePiper_COUNT ? FavouritePiper_TAGS[id] : "UNDEFINED"; }
  int FavouritePiper_fromCString(char const * tag) { /* strcmp against each tag; FavouritePiper_COUNT if none matches */ }
#+END_SRC

=FavouritePiper_fromCString= uses =strcmp=, so =pp_enum.h= includes =<string.h>=.

*** Custom tag definition
This sacrifices the protection against re-arrangement of members. The tag array has one entry for each enum member, so the compiler warns if there are more tags than members. It does not warn if there are fewer: the missing tags are null pointers.

#+BEGIN_SRC c
  #include "my_tagged_enum.h"

  ENUM_DESCRIBE_EXPLICIT(FavouritePiper,
                         "Willie Clancy",
                         "Seamus Ennis",
                         "Tommy Reck"
      );
#+END_SRC

... which expands to ...

#+BEGIN_SRC c
  static char const * FavouritePiper_TAGS[FavouritePiper_COUNT] = {
      "Willie Clancy",
      "Seamus Ennis",
      "Tommy Reck"
  };

  char const * FavouritePiper_asCString(int id) { return (unsigned)id < (unsigned)FavouritePiper_COUNT ? FavouritePiper_TAGS[id] : "UNDEFINED"; }
  int FavouritePiper_fromCString(char const * tag) { /* as above, against the explicit tags */ }
#+END_SRC

** Further enum macros
| Macro | Result |
|-|-|
| =ENUM_COUNT(Name)=, =ENUM_MAX(Name)= | =Name_COUNT= and =Name_COUNT - 1= |
| =ENUM_UNKNOWN(Name)= | the value that =Name_fromCString= returns for an unknown tag (=Name_COUNT=) |
| =ENUM_DESCRIPTOR(Name)=, =ENUM_DECODER(Name)= | the function names =Name_asCString= and =Name_fromCString= |
| =ENUM_EACH(Name, id, statements)= | runs the statements once for each member, with =int id= from 0 |
| =ENUM_EXTEND(Base, Ext)=, =ENUM_TYPE_EXTEND=, =TAGGED_ENUM_EXTEND=, =TAGGED_ENUM_TYPE_EXTEND= | an enum whose members, from =ExtIDs=, continue after =Base_COUNT= |
| =EXTENDED_ENUM_DESCRIBE(Base, Ext)= | =Ext_asCString= and =Ext_fromCString=, which also cover the members of =Base= |
| =ENUMERATED_ARRAY(Name)= | ={ &WILLIE_CLANCY_, &SEAMUS_ENNIS_, ... }=: one element address for each member, in member order. =ELNAME(WILLIE_CLANCY)= names an element (=WILLIE_CLANCY_=). |
| =ENUMERATED_ARRAY_CAST(Name, T)= | the same, with each address cast to =T= |


* Unit tests
CTest runs these tests:
- =tests= :: C++20 tests that use [[https://github.com/catchorg/Catch2][Catch2]] v2.13.9 (vendored in =vendor/catch=). [[./test/pp_iter_test.cpp]] tests =pp_iter.h= (argument counting, emptiness tests and the iteration macros), and [[./test/pp_enum_test.cpp]] tests =pp_enum.h=.
- =c_tests= :: [[./test/pp_c_test.c]], which checks both headers from C, compiled as strict C99.
- =embed_tests= and =embed_tests_no_va_opt= :: check the embedding mode (see [[#embedding-the-macros-in-another-generators-header][Embedding the macros in another generator's header]]), with =__VA_OPT__= and with =PP_HAS_VA_OPT= forced to 0. Like =header_up_to_date=, CMake adds them only if it finds Ruby.
- =header_up_to_date= :: checks that =pp_iter.h= is the output of =pp_iterators.rb=, so that a change to the generator is not committed without the regenerated header. CMake adds this test only if it finds Ruby.

The Nix flake supplies a development shell with CMake, GCC, Clang and Ruby. Run the commands below inside =nix develop=, or enter the directory with direnv.

=CMakePresets.json= has a preset for each compiler: =gcc=, =clang= and =msvc= (Windows only, with the Visual Studio generator). Each preset builds in =build/<preset>=. The presets need CMake 3.21 or later.

** Building unit tests
#+begin_src sh
  cmake --preset gcc
  cmake --build --preset gcc
#+end_src

** Running unit tests
#+begin_src sh
  ctest --preset gcc
#+end_src

All tests should pass. Run =./build/gcc/tests= for the Catch2 report (95 assertions in 11 test cases). Replace =gcc= with =clang= to build and test with Clang.

** Continuous integration
The GitHub Actions workflow [[./.github/workflows/ci.yml]] runs the =gcc= and =clang= presets on Linux, in the Nix development shell, and the =msvc= preset on Windows.

** Quick MSVC check
[[./tools/compiler_explorer.rb]] compiles and runs =test/pp_c_test.c= with the latest MSVC on [[https://godbolt.org][Compiler Explorer]], as C and as C++, with =/Zc:preprocessor=. Use it to check a change with MSVC before you push. It sends the source and both headers to godbolt.org.
#+begin_src sh
  tools/compiler_explorer.rb          # exit status 0 if both checks pass
  tools/compiler_explorer.rb --help   # other compilers, options and sources
#+end_src

* References / prior art
- I initially encountered the variadic macro counting logic in [[https://groups.google.com/forum/#!topic/comp.std.c/d-6Mj5Lko_s][this post]] by Laurent Deniau. His solution was refined by arpad. and zhangj to handle the no-argument case; =pp_iter.h= uses =__VA_OPT__= for that case instead.
- The recursive implementations of PP_EACH, PP_EACH_IDX, PP_PAR_EACH_IDX and PP_COMMA_EACH are based on an [[http://saadahmad.ca/cc-preprocessor-metaprogramming-2/][excellent series of posts]] by Saad Ahmad.
- The non-recursive implementations on the =non-recursive= branch are based on [[https://codecraft.co/2014/11/25/variadic-macros-tricks/][this blog post]] by Daniel Hardman (PP_EACH) and [[http://ptspts.blogspot.ie/2013/11/how-to-apply-macro-to-all-arguments-of.html][this (anonymous) blog post]] (PP_EACH_IDX and PP_PAR_EACH_IDX).
